## Design Specificity Verdict

**시각적으로는 이 게임만의 것이지만, 행동과 상태 관리는 아직 검수 도구 단계다.** 세 캐릭터의 추격 대형, 오피스 소품, 저녁 배경, 엘리베이터 목적지는 `부장님 피해서 퇴근하기`에 정확히 맞는다. 반면 충돌 좌표, 장애물 생명주기, 예고 타이밍, 결과 전환은 전용 아트의 완성도를 받쳐주지 못한다.

자동 탐지기는 대상 HTML에서 0건을 보고했다. 이는 정적 마크업 금지 패턴이 없다는 뜻일 뿐이며, 실제 핵심 결함은 CSS cascade와 런타임 상태·좌표 변환에서 발생한다. 브라우저 오버레이 삽입은 보안 정책으로 차단되어 사용자에게 노출된 오버레이는 없고, 대신 세 데스크톱 해상도의 DOM 좌표와 계산 스타일을 직접 대조했다.

## Overall Impression

초반에는 오피스 코미디 추격과 즉각적인 점프·슬라이드 포즈가 잘 먹힌다. 그러나 첫 장애물부터 지나간 오브젝트가 화면에 얼어붙고, 디버그 판정과 실제 코어 판정이 달라지면서 게임이 요구하는 핵심 신뢰가 무너진다. 가장 큰 기회는 장식을 더하는 것이 아니라 **하나의 좌표계·하나의 생명주기·하나의 행동 신호**로 화면과 물리를 다시 묶는 것이다.

## What's Working

- 오피스 탈출이라는 판타지, 캐릭터 순서, 소품, 엘리베이터 목적지가 설명 없이도 읽힌다.
- Space/아래 화살표 입력은 즉시 포즈와 상태에 반영되고, Escape 일시정지는 진행도를 정확히 멈춘다.
- 1280×720, 1440×900, 1920×1080에서 문서 자체의 가로·세로 overflow는 없고 104px 행동 버튼 규격은 유지된다.

## Priority Issues

### [P1] 해결된 장애물이 화면에 얼어붙는다

**왜 중요한가:** 지나간 위험과 다음 위험을 구분할 수 없고, 후반에는 캐릭터 주변에 의자·서랍·카트·표지·수집물이 쌓여 충돌 원인을 읽을 수 없다.

**증거:** 런타임은 `node.hidden = true`를 설정하지만 `.oe2-object { display:block; }`이 이를 덮어쓴다. 브라우저에서 `hidden=true`인 노드의 계산값이 실제로 `display:block`이었고, 1440×900에서 14개, 1920×1080에서 18개 오브젝트가 계속 화면과 교차했다.

**수정 방향:** 해결·화면 이탈 오브젝트는 확실히 `display:none`이 되게 한다. 피격 연출을 남기고 싶다면 충돌을 즉시 해제한 별도 잔해 레이어에서 짧게 밀려난 뒤 제거한다. hit/avoid/collect/offscreen 네 경로 모두 브라우저 회귀 테스트로 고정한다.

**Suggested command:** `$impeccable harden`

### [P1] 실제 판정, 도윤 스프라이트, 디버그 상자가 서로 다른 좌표계를 쓴다

**왜 중요한가:** 플레이어가 보는 접촉과 게임이 계산하는 접촉이 달라져 `피했는데 맞음`과 `겹쳤는데 안 맞음`이 모두 생길 수 있다. 판정 보기 도구마저 잘못돼 튜닝 근거도 신뢰할 수 없다.

**증거:** 1280×720 기준 코어 도윤 몸체는 약 72×144px인데 청록 디버그 상자는 약 146×292px로 양축 약 2배이고, 왼쪽 기준도 약 93px 어긋났다. 도윤 host는 `left`를 캔버스 왼쪽으로 사용하므로 포즈 캔버스 폭이 커지는 슬라이드에서 화면상 중심이 수십 픽셀 이동한다. A/B 시안은 도윤 X·바닥 높이가 다른데 장애물은 항상 31%·8.5% 기준으로 그린다. 배경에 포함된 큰 의자도 실제 충돌 장애물처럼 보여 위험 구분을 방해한다.

**수정 방향:** 발바닥 중심 하나를 화면 앵커로 정하고 도윤·장애물·예고·디버그 상자가 같은 world-to-screen 함수를 사용하게 한다. 디버그 상자는 `snapshot.playerRect`와 `collisionRect`를 직접 렌더한다. 배경 가구는 충돌 레인과 시각적으로 분리한다.

**Suggested command:** `$impeccable harden`

### [P1] `NOW` 신호가 사람이 반응하기엔 너무 늦다

**왜 중요한가:** 안내를 보고 정확히 입력한 초보자가 실패한다. 이는 난도가 아니라 불공정으로 느껴진다.

**증거:** ACT 전환은 점프 0.16초, 슬라이드 0.15초 전에 발생한다. PREP은 1.0~1.35초 전에 나타나지만 그때 입력하면 점프·슬라이드가 장애물 전에 끝나고, `NOW`를 기다리면 일반적인 시각 반응 시간보다 짧다. 현재 자동 테스트는 `inputReady`가 된 정확한 프레임에 기계적으로 입력하므로 이 문제를 놓친다.

**수정 방향:** PREP은 위험 설명, ACT는 실제로 반응 가능한 0.45~0.75초 창으로 재정의한다. 입력을 받았으면 즉시 `입력 완료`를 보여주고 필요한 경우 예약 실행한다. 첫 점프·슬라이드는 더 넓은 학습 창을 사용한다.

**Suggested command:** `$impeccable onboard`

### [P1] 상단 UI가 플레이필드를 가리고 시선을 빼앗는다

**왜 중요한가:** 자동 러너의 핵심은 오른쪽 전방 읽기인데 가장 강한 대비가 상단 상태판과 검수 도구에 몰려 있다.

**증거:** 게임 HUD는 79~98px이고, dev 툴바는 세 해상도 모두 91px 높이로 플레이필드 위에 겹친다. 1280×720에서는 HUD와 툴바가 화면 상단 25.7%까지 차지한다. 가장 큰 텍스트인 `17:58 · 퇴근까지`는 실제로 변하지 않아 정보 가치도 낮다.

**수정 방향:** 실제 플레이가 시작되면 dev 툴바를 자동 접고 바깥 도킹/한 개의 펼치기 버튼으로 바꾼다. 게임 HUD는 진행·피격/보호·수집만 작은 한 줄 또는 가장자리 칩으로 남긴다. `17:58`은 분위기용이면 작게 `현재 시각`으로, 정보용이면 실제 상태로 바꾼다.

**Suggested command:** `$impeccable distill`

### [P2] 회복과 종료가 명확한 상태 전환으로 보이지 않는다

**왜 중요한가:** 피격 후 계속 플레이할 수 있다는 장점이 오히려 버그처럼 보이고, 도착의 감정적 보상이 약해진다.

**증거:** 피격 카운터는 `7/3`, `17/3`처럼 분모를 넘는다. 버튼의 `pressed` 클래스는 제거되지 않는다. 일시정지 직후 진행 바 CSS 보간이 조금 더 움직인다. 결과가 떠도 포커스는 JUMP에 남고 하단 조작이 활성 상태이며 재도전이 없다.

**수정 방향:** `피격 7회 · 붙잡힘 기준 3회 초과`처럼 상태를 정직하게 표시하거나 3회 이후에는 `붙잡힘` 상태만 보인다. 피격 정지·접촉 스파크·짧은 밀림과 무적 표시를 묶고, 결과 진입 시 게임 레이어를 inert 처리해 결과 CTA로 포커스를 이동한다. dev 결과에는 즉시 재도전을 제공한다.

**Suggested command:** `$impeccable harden`

## Persona Red Flags

**Alex — 숙련 플레이어:** 64초 동안 점프/슬라이드가 정확히 번갈아 나와 두 번만 학습하면 이후는 읽기보다 암기 리듬이 된다. 결과에서 바로 재도전할 수 없고 dev 툴바를 따로 숨겨야 한다.

**Jordan — 첫 플레이어:** 시작 설명·카운트다운·키 힌트가 없고 `JUMP/SLIDE/NOW`가 한국어 UI와 섞인다. `NOW`를 믿으면 늦고 PREP에 누르면 빠르다. 남은 장애물이 누적돼 무엇이 위험한지도 사라진다.

**Sam — 키보드·접근성 사용자:** 점프/슬라이드/Escape는 지원하지만 진행 바에 수치형 접근성 값이 없고, 결과 포커스가 JUMP에 남으며 이전 조작이 비활성화되지 않는다. 오브젝트 컨테이너의 live region과 남아 있는 이미지들이 과도한 읽기 부담을 만들 수 있다.

## Minor Observations

- 18개 장애물이 점프→슬라이드를 끝까지 엄격히 반복해 중후반 리듬과 클라이맥스가 약하다.
- 부장님은 시각적으로 쫓지만 피격·회복과 거리가 연동되지 않아 위협이 장식에 머문다.
- 배경 review를 끄면 Office A/B/C가 같은 승인 배경으로 폴백해 36초 동안 공간 진행이 거의 식별되지 않는다.
- W/S 입력을 지원하지만 화면과 접근성 라벨에는 충분히 드러나지 않는다.
- 하단 104px 원형 버튼은 PC 키보드 중심 게임의 보조 입력치고 시각 비중이 크다.
- 코어·통합 테스트 49개는 통과했지만 렌더 좌표, 계산된 `hidden`, 포즈 앵커, 결과 포커스는 검사하지 않는다.
- 현재 V2의 `docs/REQUIREMENTS.md`가 없고 legacy 요구사항과 수정 계획만 남아 판정 계약이 다시 흔들릴 위험이 있다.

## Questions to Consider

- 이 게임의 기본 난도는 `처음 해도 공정하게 완주`인가, `두세 번 재도전해 패턴 숙달`인가?
- 장애물 피격 뒤 오브젝트는 즉시 사라져야 하는가, 짧게 튕겨나가는 비충돌 잔해가 되어야 하는가?
- `17:58`은 세계관 장식인가, 플레이 정보인가?
- 남은 60초를 계속 점프/슬라이드 교대로 채우는 것이 의도한 재미인가, 후반에는 조합·수집·부장 압박으로 리듬을 바꿀 것인가?
- dev 페이지는 QA 대시보드인가, 사용자에게 보여줄 플레이 빌드인가?
