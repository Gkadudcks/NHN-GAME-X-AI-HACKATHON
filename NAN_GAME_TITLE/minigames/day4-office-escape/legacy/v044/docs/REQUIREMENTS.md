# DAY 4 퇴근 미니게임 구현 요구사항

이 문서는 `부장님 피해서 퇴근하기`의 기획·구현·검증 단일 기준이다. 대화 컨텍스트가 압축되거나 새 작업에서 루프를 재개할 때 먼저 읽는다.

## 루프 체크포인트

- [V042 · 0–3시간](DAY4_OFFICE_ESCAPE_LOOP_V042.md): UI·공간 이동·속도·장애물 다양성·VFX·조작감 1차 개선, 독립 평가, 실행 파일 SHA-256.
- [V043 · 3–6시간](DAY4_OFFICE_ESCAPE_LOOP_V043.md): 보행 위상·장소 스탬프·원거리 카메라 동결, 후속 실플레이에서 확인한 collision cue P1과 V044 수용 기준, 실행 파일 SHA-256.
- [V044 · 6–9시간](DAY4_OFFICE_ESCAPE_LOOP_V044.md): collision-aware cue·exactly-once 입력·반응형 HUD·거리 기반 장소·pause 접근성을 동결하고, 네 독립 평가·최종 회귀·실행 파일 SHA-256을 기록했다.

## 1. 확정 방향

- 장르: 2D 횡스크롤 자동 달리기
- 플레이 시간: 기본 64초, 허용 범위 60~75초
- 입력: 점프 + 슬라이드. 좌우 이동 없음
- 지원 환경: PC 데스크톱 브라우저 전용. 최소 1280×720이며 1440×900을 주 검수, 1920×1080을 와이드 검수 기준으로 사용한다. 모바일·터치·세로 화면은 완료 기준에서 제외한다.
- 구간: 사무실 → 회의실·복합기 복도 → 엘리베이터 로비
- 감정: “오늘만은 정시에 퇴근한다”는 가벼운 긴장과 오피스 코미디
- 레퍼런스 사용법:
  - Mario: 첫 위험은 쉽게, 위험의 시각 언어를 반복 학습, 실패 후 바로 회복
  - Mario Run: 자동 전진으로 입력을 한두 개의 의미 있는 타이밍에 집중
  - Celeste: 입력 버퍼·코요테 타임·관대한 충돌 보정
  - Danganronpa V3 Death Road of Despair: 동료가 함께 달리는 탈출 압박과 연속 함정의 리듬만 취하고, 의도적 초고난도·가려진 즉사는 제외
  - 제외: 의도적 불공정, 미끄러운 관성, 암기 전제 즉사, 긴 재시작

## 2. 플레이 규칙

### 이동과 입력

- 도윤은 자동으로 오른쪽으로 달린다.
- `Space`, `ArrowUp`, `W` 또는 점프 버튼으로 점프한다.
- `ArrowDown`, `S` 또는 슬라이드 버튼을 누르는 동안 슬라이드한다. 일반 입력은 아주 짧게 눌러도 실제 낮은 판정과 전용 포즈를 80ms까지 함께 유지하며, 오래 누르면 입력을 놓을 때까지 연장한다. 장애물의 채운 `지금` 신호에서 받은 의미 입력은 위험의 실제 충돌 종료까지 커밋한다.
- 점프 입력 버퍼 150ms, 코요테 타임 120ms를 제공한다.
- 위험 오브젝트의 실제 충돌 상자는 보이는 크기보다 15~20% 작게 둔다.

### 화면 좌표와 입력 감각

- 도윤의 화면상 발바닥 중심 X는 플레이필드 너비의 30~35%에 고정하며, 정상 플레이 중 기준점 오차는 ±2px 이하여야 한다.
- 점프는 도윤의 Y축만 바꾸고, 자동 전진은 배경·바닥·장애물의 공통 월드 이동으로 표현한다. 피격 반동 외의 공중 좌우 이동과 air steering은 두지 않는다.
- 입력 이벤트부터 버튼·부착 표식·상태줄의 첫 시각 반응은 다음 렌더 프레임 이내여야 한다. 위험 신호 밖의 직접 점프는 50ms 안에 상승하며, `미리 탭`으로 예약한 점프는 즉시 `입력 완료`를 표시하고 실제 충돌 약 0.26초 전의 물리 ACT에서 한 번만 상승한다.
- 짧게 누른 점프와 길게 누른 점프의 최고점 차이는 720p 기준 55px 이상이어야 한다. 길게 누를 때 정점 부근 중력을 기본값의 0.5~0.65배로 낮춰 착지 조정 시간을 제공한다.
- 슬라이드 판정과 전용 포즈는 같은 프레임에 바뀌며, 시작과 해제 반응은 각각 80ms 이하여야 한다. 80ms 최소 커밋은 코어 시뮬레이션 시간으로 계산하고 포즈·플레이어 판정·dev 히트박스가 같은 `sliding` 상태를 사용한다. 정지 원화를 회전·기울여 슬라이드로 대체하지 않는다.
- 점프·슬라이드 입력은 키보드·포인터·보조기술 click에서 같은 상태 전이와 타이밍 규칙을 사용한다. 점프 예약은 `queued → executed → resolved` 단일 레코드로 관리하고, 동일 위험의 중복 입력은 두 번째 점프를 만들지 않는다. 포인터 취소는 같은 `pointerId`와 소유 토큰의 대기 예약만 취소하며 다른 포인터나 키보드 예약을 건드리지 않는다.

### 위험과 회복

- 낮은 장애물은 점프, 머리 높이 장애물은 슬라이드로 피한다.
- 새 위험 유형은 안전한 단독 예시로 먼저 소개한 뒤 조합한다.
- 모든 위험은 현재 속도와 보이는 이미지 폭이 아니라 플레이어 body와 위험 collision rect의 첫 접촉을 기준으로 최소 1.25초 전에 실루엣·행동 아이콘·바닥 표식 중 두 가지로 `준비`를 예고한다. 점프는 충돌 약 0.55초 전부터 `미리 탭` 예약을 받고 약 0.26초 전에 물리 실행하며, 첫 학습 의자만 0.90초 전부터 예약을 받는다. 슬라이드는 약 0.75초 전에 같은 위치의 채운 화살표와 `지금` 행동 신호로 한 번만 전환한다.
- 한 패턴은 준비 1.25초 이상 → 입력 가능/물리 실행 → 회복의 리듬을 가진다. 연속 위험은 앞 위험의 실제 collision exit부터 다음 collision entry까지 0.5초 이상, 앞 위험의 물리 ACT부터 다음 필수 input-ready까지 0.5초 이상을 모두 지킨다. 첫 등장 위험 사이와 서로 다른 행동을 잇는 첫 조합은 이 하한보다 넓게 둔다.
- 모든 장애물은 공통 월드 속도에 묶고, 화면 오른쪽에서 충돌 지점까지 끊김 없이 이동한다. 타입별 독립 슬라이드 애니메이션이나 갑작스러운 완성 크기 출현은 금지한다.
- 피격 후 800ms 무적과 짧은 속도 저하를 제공하고 플레이는 계속된다.
- 실제 위험 충돌 상자의 오른쪽 끝이 플레이어의 왼쪽 끝을 완전히 지난 첫 프레임에만 회피 성공을 확정한다. 일반 회피는 도윤 뒤의 작은 청록 체크를 약 260ms 표시하고, 첫 점프·슬라이드만 1200ms 통과 문구를 추가한다. 피격·하린 보조에는 성공 이벤트를 보내지 않는다.
- 서하린은 항상 동행하며 첫 위기 안내와 1회의 자동 보조를 제공한다.
- 보조 성능은 호감도와 무관하며, 호감도는 대사 표현에만 영향을 준다.

### 판정과 피격 가독성

- 플레이어 이미지와 논리 body는 같은 하단 중앙 앵커를 사용하며, 화면상 발바닥 중심 오차는 4px 이하여야 한다.
- 장애물 판정은 불투명 위험 실루엣 안에 있어야 하며, 보이는 기준 상자에서 양축 총 18% inset 규칙을 유지한다.
- dev 화면에는 플레이어 body, 장애물 기준 상자, 실제 충돌 상자를 구분해 표시하는 `Hitbox` 토글을 둔다. 본편에서는 디버그 상자를 노출하지 않는다.
- 본편에서는 바닥 그림자, 통과 여유선, 접촉 스파크를 실제 판정 위치에 맞춰 그림만 보고도 안전 범위를 예상할 수 있게 한다.
- 피격 시 40~60ms의 짧은 정지, 접촉점 효과, 캐릭터 플래시를 제공하되 조작 복귀와 800ms 무적 규칙은 유지한다.

### 수집과 결과

- 선택 수집물: 출입카드, 휴대폰, 백업 USB.
- 수집물은 결과 상세와 콤보에만 반영하고 등급·스토리 진행을 잠그지 않는다.
- 피격 0회: `perfect`
- 피격 1~2회: `close`
- 피격 3회 이상: `caught`
- `caught`도 정상 완료이며 “10분 확인 업무 후 퇴근”으로 본편에 복귀한다.
- 결과 계약:

```js
{
  grade: "perfect" | "close" | "caught",
  caught: boolean,
  elapsed: number,
  hitCount: number,
  collectedItems: string[],
  maxCombo: number
}
```

## 3. 화면과 아트

- 기존 승인 배경을 픽셀 변경 없이 복제한 미니게임 전용 안정 ID를 세 구간의 원경·색감 기준으로 사용하되, 한 장의 고정 배경만으로 코스를 구성하지 않는다.
  - `minigame_background.office_escape.office`
  - `minigame_background.office_escape.corridor`
  - `minigame_background.office_escape.elevator`
- 도윤은 측후면 중심으로 얼굴 노출을 줄이고 자연스러운 성인 비율을 유지한다.
- 캐릭터, 배경, 소품을 각각 별도 에셋으로 관리한다.
- `distance`에 연결된 최소 3층 패럴랙스를 사용한다. 권장 속도 계수는 원경 0.15, 중경 0.4, 바닥·장애물 1.0이다.
- 바닥 이음선과 가구 열은 매 프레임 이동해야 하며, 8~12초마다 문·유리 파티션·출입 게이트·엘리베이터 문턱 중 하나가 도윤을 실제로 지나가야 한다.
- 구간 전환은 배경 페이드만으로 처리하지 않는다. 사무실 → 복도 → 엘리베이터 로비의 공간·시간대가 순방향으로 이어져야 한다.
- 초반 `사무실 출구`와 기존 `유리 회의실` 사이의 약 20초 공백은 17% 지점의 비충돌 `회의실 7F` 유리 랜드마크로 나눠, 0~31%에서도 약 10초마다 물리 구조가 실제로 화면을 통과하게 한다.
- 플레이 중 지속 HUD는 PC 플레이필드의 16% 이하로 제한한다. 위험·진행·수집만 상단 한 줄에 남기고 하단 조작은 마우스 보조용 소형 키 힌트로만 유지한다.
- 행동 명령은 18px 이상, 위험·진행 수치는 18px 이상으로 한다. 키보드를 기본 입력으로 사용하고 마우스 클릭은 같은 상태 전이를 사용하는 보조 입력으로 유지한다.
- 위험 예고는 우측 고정 웹 카드가 아니라 해당 장애물의 바닥·머리 높이에 붙인다. 플레이필드 중앙 55%와 도윤 진행 방향은 상시 패널로 가리지 않는다.
- 캐릭터 시드 프레임이 승인되기 전에는 애니메이션 스트립을 생성하지 않는다.
- 런타임 캐릭터에는 VN 대화용 정면 초상화를 사용하지 않는다. 기존 계획 ID `minigame_character.doyun.jump.right`, `minigame_character.doyun.slide.right`, `minigame_character.harin.run.right`, `minigame_character.harin.assist.right`, `minigame_character.boss.chase.right`, `minigame_character.boss.call.right`를 채워 재사용한다.
- 도윤·하린·부장님은 동일한 우향 3/4 시점, 발바닥 기준선, 외곽선 굵기, 명도 대비를 사용한다. established 얼굴·머리·체형·복장·소품은 변경하지 않는다.
- 달리기·추격 상태는 동일한 우향을 유지한 두 보폭을 500ms마다, 즉 1초에 두 번 교대한다. A는 캐릭터 기준 왼발과 오른팔이 전진하고, B는 오른발과 왼팔이 전진해야 하며 임시 L/R 색상 마커로 해부학적 소유권을 증명한 뒤 마커를 제거한다. 하린·부장님은 프레임 전환 때 발을 하단 중앙에 고정한 채 70ms 동안 105%→100%로 자세만 강조하고, 도윤에는 이 확대를 적용하지 않는다. 점프·슬라이드·도움·호출 상태에서는 해당 전용 정지 포즈를 유지한다.
- 보조 보폭이 없거나 이미지 로드가 실패하거나 `prefers-reduced-motion`이 켜져 있으면 승인된 기본 프레임 하나로 안전하게 폴백한다.
- 승인 전 draft/review 파일은 본편 런타임의 `active_version`으로 지정하지 않는다.
- 이미지 생성·수정은 `docs/art/` 규칙과 `assets/art/manifests/art-assets.json`을 따른다.
- DAY 4 전용 이미지는 `NAN_GAME_TITLE/minigames/day4-office-escape/assets/art/` 아래에서만 관리하고, 본게임 대화형 `characters/`, `backgrounds/`, `event_cg/`에 섞지 않는다.
- 런타임은 `OfficeEscapeArtAssets.resolve(id)`를 사용하며 본게임용 `ArtAssets`에 의존하지 않는다.

## 4. 구조와 호환성

- 본편 공개 API `OfficeEscapeMinigame.start({ onComplete })`, `pause()`, `resume()`을 유지한다.
- 순수 규칙은 `core.js`, DOM·입력·연출과 공개 API는 `index.js`에 둔다.
- DAY 4 본편의 저장 필드 `minigameResult`와 기존 `grade`, `caught` 의미를 유지하며 결과 필드를 확장한다.
- 개발 화면은 `NAN_GAME_TITLE/minigames/day4-office-escape/dev/index.html`로 만든다.
- 공용 개발 도구 스타일은 `NAN_GAME_TITLE/minigames/shared/dev.css`로 분리해 다른 미니게임 개발 화면도 재사용한다.
- 테스트 전용 옵션은 공개 결과 계약을 바꾸지 않으며 dev 화면에서만 주입한다.

## 5. 루프 지침

1. 이 문서, `AGENTS.md`, 관련 기존 코드, `docs/art/`를 읽는다.
2. 변경하려는 책임을 가진 기존 모듈이 있는지 먼저 검색한다.
3. 한 루프에서 게임 감각 또는 시각 요소의 큰 축 하나만 바꾼다.
4. 규칙 변경은 core 테스트, 통합 변경은 DAY 4 테스트를 먼저 갱신한다.
5. 이미지 변경 시 manifest 계획 → 생성 로그 → draft/review → 검증 → 사용자 승인 → approved/active 순서를 지킨다.
6. `python scripts/validate_art_assets.py`와 `node --test tests/*.test.js minigames/*/tests/*.test.js`를 실행한다.
