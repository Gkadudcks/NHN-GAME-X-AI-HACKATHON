# DAY 4 V2 배경 전환·조작 UI 수정 계획

작성일: 2026-08-04

상태: 구현 완료 · 신규 배경 사용자 승인 대기

## 1. 확정 결정

- 시안 A/B/C의 화면 구성과 공통 물리 코어는 유지한다.
- 점프·슬라이드 버튼은 세 시안 모두 승인안 1인 `104px 원형 링`으로 통일한다.
- 좌상단은 세계관 시각 `17:58`만 남기고 `· 64s` 형태의 남은 초 표시는 제거한다. 실제 진행 정보는 기존 진행도 바로만 전달한다.
- 서로 다른 완성 배경을 한 줄로 붙여 화면 전체를 수평 이동시키는 방식을 폐기한다.
- 배경은 구간 안에서 2~3%만 미세 이동하고, 구간 종료 전 0.7초 동안 다음 배경과 교차 전환한다.
- 상시 이동하던 합성 유리·기둥 레이어는 전부 제거한다. 속도감은 배경의 미세 이동과 바닥·장애물·수집물의 실제 월드 이동으로 만든다.
- Office B/C, Corridor B, Lobby A/B는 계속 `review` 상태로 둔다. 수정 화면 캡처를 사용자에게 보여준 뒤 별도 승인 없이는 `approved` 또는 `active_version`으로 승격하지 않는다.

## 2. 해결하려는 문제

현재 `index.js`는 11장의 완성 배경을 각각 한 화면 너비로 나열하고 진행률에 따라 전체 트랙을 약 10화면만큼 이동한다. 서로 원근·가구·조명이 다른 이미지의 경계가 화면을 가로질러 지나가므로 공간이 이어지기보다 사진이 밀려가는 것처럼 보인다.

여기에 CSS로 만든 반투명 유리판, 원경 실루엣, 기둥이 서로 다른 속도로 계속 이동한다. 이 레이어는 실제 배경의 구조와 맞물리지 않고 캐릭터 앞뒤 깊이도 불명확해 합성 티와 시각적 방해를 만든다.

이번 수정의 목표는 러너의 이동감을 없애는 것이 아니라, 이동의 근거를 `사진 이음선`에서 `게임 오브젝트와 바닥의 흐름`으로 옮기는 것이다.

## 3. 구현 범위

### 3.1 배경 렌더링

대상: `index.js`, `style.css`

1. `.oe2-background-track`은 긴 flex 트랙이 아니라 플레이필드 전체를 채우는 스택 컨테이너로 바꾼다.
2. `.oe2-background-panel` 11개는 같은 좌표에 겹쳐 놓고 기본 상태를 `opacity: 0`으로 둔다.
3. 현재 구간과 다음 구간 패널만 렌더에 참여시킨다.
   - 현재 패널: 구간 대부분에서 불투명도 1.
   - 다음 패널: 구간 종료 0.7초 전부터 불투명도 0→1.
   - 현재 패널: 같은 시간 동안 불투명도 1→0.
4. 구간 내부 진행률을 `segmentProgress = (elapsed - start) / (end - start)`로 계산한다.
5. 각 배경 이미지는 구간 시작부터 끝까지 화면 너비의 최대 2~3%만 천천히 좌측 이동한다. 이미지 가장자리가 드러나지 않도록 약 1.04배 확대된 내부 캔버스에서 이동한다.
6. 전환 혼합값은 마지막 0.7초에만 0→1이 되며, 급격한 밝기 변화가 없도록 `ease-in-out` 곡선을 적용한다.
7. 일시정지 중에는 코어의 `elapsed`가 멈추므로 배경 이동과 교차 전환도 같은 프레임에서 정지해야 한다. 재개 시 CSS 독립 애니메이션을 새로 시작하지 않고 코어 시간에서 다시 계산한다.
8. 모든 배경은 시작 시 미리 로드하며, 현재·다음 이미지 중 하나가 로드되지 않았을 때는 현재 정상 이미지의 불투명도를 1로 유지해 빈 화면을 방지한다.
9. `prefers-reduced-motion`에서는 미세 이동을 제거하되 0.7초 교차 전환은 유지한다.

### 3.2 불필요한 패럴랙스 제거

대상: `index.js`, `style.css`

- DOM에서 `.oe2-far-layer`, `.oe2-mid-layer`, `.oe2-thresholds`를 제거한다.
- 관련 CSS와 `--oe2-far-x`, `--oe2-mid-x`, `--oe2-near-x` 갱신 코드를 삭제한다.
- 시안 B에만 적용되던 `.oe2-mid-layer` 위치 보정도 함께 삭제한다.
- 실제 장애물·수집물·바닥 가이드의 월드 이동은 유지한다.
- 새 유리, 문틀, 기둥 이미지는 이번 수정에서 만들지 않는다. 이후 화면에 공간 전환 표식이 정말 부족하다고 확인될 때만 별도 에셋 검수 작업으로 분리한다.

이 결정은 이전 V044의 상시 3층 패럴랙스 규칙을 V2에서 대체한다. V2는 완성 배경의 미세 이동과 실제 전경 오브젝트 흐름을 사용하며, 시각적으로 맞지 않는 가짜 중경을 규칙 충족만을 위해 유지하지 않는다.

### 3.3 버튼 1안 적용

대상: `style.css`, 필요한 경우 `index.js`

- `.oe2-action`의 크기를 PC 세 해상도에서 `104×104px`로 고정한다.
- A/B/C의 버튼 크기·사각형 모양·타이포 재정의는 제거하고 위치 차이만 시안별로 유지한다.
- 점프와 슬라이드는 같은 링 두께, 아이콘 크기, 라벨 계층, 키 힌트 위치를 사용한다.
- 점프는 기존 앰버 계열, 슬라이드는 청록 계열로 행동만 구분한다.
- 기본, hover, `:focus-visible`, pressed/active, disabled 상태가 같은 구조 안에서 명확히 달라져야 한다.
- 눌림 피드백은 위치가 2px 내려가는 짧은 반응만 사용하고 반복 펄스나 장식 애니메이션은 추가하지 않는다.
- 버튼은 캐릭터 진행축과 장애물 예고 영역을 가리지 않아야 한다.

### 3.4 남은 초 제거

대상: `index.js`, 관련 테스트

- `formatClock(snapshot)`에서 남은 초 계산과 `· Ns` 출력을 제거한다.
- 좌상단에는 고정된 `17:58`만 표시한다.
- 남은 시간 접근성 문구도 중복 제공하지 않는다. 진행 상태의 단일 기준은 진행도 바의 값과 접근성 라벨이다.
- 진행도 바, 구간명, 수집물, 일시정지 기능은 변경하지 않는다.

## 4. 변경하지 않는 범위

- `core.js`의 64초 코스, 점프·슬라이드 물리, 충돌, 등급, 하린 보조 규칙
- A/B/C의 HUD 배치, 캐릭터 위치, 캐릭터 불투명 높이와 바닥 기준선
- 배경 노출 순서 `사무실 A-B-C-A-B-C → 복도 A-B → 로비 A-B-A`
- 승인된 캐릭터·소품·기존 Office A/Corridor A/Elevator 이미지 원본
- `OfficeEscapeMinigame.start`, `pause`, `resume` 및 결과·저장 계약
- 모바일·터치·세로 화면 대응

## 5. 작업 순서

1. 현재 배경 패널과 시안별 버튼의 DOM·CSS 계약을 테스트에 기록한다.
2. 배경 패널을 절대 배치 스택으로 전환하고 구간별 현재/다음 패널 계산을 구현한다.
3. 0.7초 교차 전환, 2~3% 미세 이동, 이미지 로드 실패 폴백, 일시정지 동결을 연결한다.
4. 합성 원경·유리·기둥 DOM과 CSS 및 런타임 변수를 제거한다.
5. 버튼을 104px 원형 링으로 통일하고 세 시안의 위치·상태·포커스를 정리한다.
6. 남은 초 출력을 제거하고 좌상단을 `17:58`로 고정한다.
7. 자동 테스트와 데스크톱 브라우저 캡처를 수행한다.
8. 검수 캡처를 사용자에게 제시한다. 신규 배경 승격은 이 단계의 명시적 승인 이후 별도 작업으로 수행한다.

## 6. 검증 기준

### 자동 검증

- 구간 시작, 전환 0.7초 직전, 전환 중간, 구간 종료에서 현재·다음 패널의 불투명도 합이 1이어야 한다.
- 전환 시간 밖에는 동시에 보이는 패널이 하나뿐이어야 한다.
- 64초 동안 배경 순서가 기존 11구간 데이터와 정확히 일치해야 한다.
- 일시정지 중 같은 snapshot을 반복 렌더해도 배경 위치와 혼합값이 변하지 않아야 한다.
- 재개 직후 큰 프레임 간격이 들어와도 배경 패널이 두 구간 이상 건너뛰거나 빈 화면이 되지 않아야 한다.
- `.oe2-far-layer`, `.oe2-mid-layer`, `.oe2-thresholds`와 관련 CSS 변수가 production DOM/CSS에 남지 않아야 한다.
- A/B/C의 점프·슬라이드 버튼 계산 크기가 모두 104×104px이고 원형이어야 한다.
- 좌상단 텍스트에 초 단위 숫자와 `s`가 없어야 하며 진행도 값은 기존과 같아야 한다.
- 기존 코어·DAY 4 통합 테스트가 모두 통과해야 한다.

### 시각 검증

- 1280×720, 1440×900, 1920×1080에서 A/B/C를 각각 확인한다.
- 각 시안에서 run, jump, slide 장면과 사무실→복도, 복도→로비, 로비→엘리베이터 전환을 캡처한다.
- 배경 이음선이나 빈 가장자리가 보이지 않아야 한다.
- 교차 전환 중 캐릭터·장애물·바닥은 흐려지거나 이중으로 보이지 않아야 한다.
- 배경 움직임이 캐릭터 달리기보다 먼저 눈에 띄지 않아야 한다.
- 삭제한 유리·기둥의 잔상이나 화면을 가로지르는 반투명 판이 없어야 한다.
- 104px 버튼이 캐릭터, 첫 장애물, 예고 신호, 진행도 바를 침범하지 않아야 한다.
- 브라우저 콘솔 error/warning과 문서 overflow가 없어야 한다.

## 7. 완료·승인 게이트

코드 수정과 자동 검증이 끝나도 신규 배경은 계속 review다. 다음 캡처 묶음을 사용자가 확인해야 이번 수정 루프를 시각적으로 완료한 것으로 본다.

- A/B/C 대표 플레이 화면 각 1장
- 사무실→복도 전환 전·중·후 3장
- 복도→로비 전환 전·중·후 3장
- 버튼 기본·hover·focus·pressed 비교 1장

사용자 승인 후에만 신규 배경 파일을 approved로 복사하고 manifest의 `active_version`을 갱신한다. 승인 전에는 review 경로의 파일을 덮어쓰거나 production 안정 ID로 활성화하지 않는다.
