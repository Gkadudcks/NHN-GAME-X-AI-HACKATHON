# DAY 4 미니게임 플레이 화면 리팩터링 결정

- 결정일: 2026-08-02
- 대상: DAY 4 미니게임 「부장님 피해서 퇴근하기」의 플레이 화면
- 상태: 다음 UI 작업의 기준으로 확정

## 1. 결정

현재 플레이 화면을 기존 UI의 개선 대상으로 보지 않고, **게임 코어와 승인 아트를 제외한 프레젠테이션 레이어 교체 작업**으로 다시 진행한다.

기존 파일을 물리적으로 즉시 삭제하지는 않는다. 비교와 복구를 위해 보존하되, 새 플레이 화면에서는 기존 DOM 계층과 CSS 시각 문법을 계승하거나 참조하지 않는다.

## 2. 유지할 것

- 결정론적 게임 코어와 충돌·입력 판정
- `OfficeEscapeMinigame.start({ onComplete })`, `pause()`, `resume()` 계약
- `grade`, `caught` 결과 계약과 DAY 4 저장 연동
- 미니게임 전용 아트 resolver와 안정적인 manifest ID
- 승인된 캐릭터·소품 이미지와 사용 가능한 배경 이미지
- 자동 테스트와 최소한의 dev harness
- 하린의 호감도와 무관한 기계적 보조 규칙

승인 이미지와 배경은 **사용 가능한 재료 목록**으로 취급한다. 존재한다는 이유만으로 새 화면에 모두 사용하거나, 새 구도를 기존 버전처럼 만드는 자산을 강제로 채택하지 않는다.

## 3. 새 플레이 화면에서 폐기할 것

- 현재 플레이 DOM 계층과 HUD 조합
- 현재 `office-escape-minigame.css`의 시각 구조
- 고밀도 계기판형 HUD와 중복 안내 문장
- 장소명 라벨·반투명 포털·별도 하단 조작 띠
- 구간별 기존 배경 교체를 중심으로 한 장면 구성
- 화면 전체에 겹쳐진 다중 패럴랙스·필터 효과
- 매 프레임 다수의 DOM 클래스와 인라인 스타일을 갱신하는 표현 방식
- 기존 구현을 전제로 작성된 surface brief의 배경·패럴랙스 수치

## 4. 플레이 화면의 새 기준

세 승인 시안은 하나를 고르는 선택지가 아니라 다음 공통 문법의 시각 기준이다.

- 얇은 단일 상단 HUD
- 화면의 주인공이 되는 큰 캐릭터와 명확한 추격 간격
- 중앙과 하단을 UI로 가리지 않는 풀블리드 플레이필드
- 유리 중경·전경 가림·바닥 접촉으로 읽히는 사무실 깊이
- 라벨이나 포털이 아니라 월드 공간에 실제로 존재하는 장애물과 문턱
- 마지막 구간에서 월드 공간으로 도착하는 엘리베이터
- 키보드 기본 입력과 두 모서리의 마우스 보조 입력
- PC 1280×720, 1440×900, 1920×1080 전용 구성

레퍼런스 PNG를 배경 이미지로 직접 사용하지 않는다. DOM/CSS와 승인 아트로 시안의 공간 비율·위계·깊이·액션 구도를 재현한다.

## 5. 구현 순서와 승인 게이트

1. 게임 로직을 연결하지 않은 1440×900 정적 플레이 화면을 먼저 만든다.
2. UI 크기, 캐릭터 비율, 추격 구도, 배경 깊이, 장애물과 엘리베이터 배치를 인앱 브라우저에서 검수한다.
3. 정적 화면이 세 시안의 공통 방향에 부합하는지 사용자 확인을 받는다.
4. 승인된 정적 화면을 1280×720과 1920×1080으로 확장한다.
5. 기존 결정론 코어의 출력만 최소한의 렌더 어댑터로 연결한다.
6. 애니메이션과 패럴랙스는 마지막에 추가하며, 전체 화면 필터와 불필요한 매 프레임 DOM 갱신을 피한다.
7. 실제 플레이 검증에서 입력·일시정지·결과·저장 계약과 프레임 안정성을 함께 확인한다.

정적 플레이 화면이 사용자 확인을 통과하기 전에는 기존 런타임을 새 UI에 연결하지 않는다.
